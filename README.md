# spoken-script-critical-reviewer

一个用于**批判性审查并重构中文口播稿**的 Agent Skill。

## 它解决什么问题

很多“口播优化”只会：
- 换标题；
- 加钩子；
- 变口语；
- 删废话；
- 强行加情绪。

这个 Skill 重点解决更底层的问题：
- 中心问题到底是什么；
- 谁为什么需要听；
- 入口是否真的与用户相关；
- 正文有没有认知推进；
- 观点有没有被证明；
- 案例有没有过度外推；
- 情绪、故事、反差是否只是包装；
- 结尾有没有形成新的判断；
- 如何改，以及为什么这样改。

## 典型使用方式

```text
请使用 spoken-script-critical-reviewer 审查这篇口播稿。
重点看逻辑、论证和传播入口，按默认完整模式输出。
```

也可以指定模式：

```text
只审不改，重点看逻辑漏洞。
```

```text
保守修改，尽量保留我原来的案例和语气。
```

```text
强重构，目标是 2 分钟知识型短视频，但不要为了传播牺牲严谨性。
```

```text
这是一份 SRT。先忽略时间码审查，再给连续口播改稿。
```

## 设计原则

1. **诊断优先于评分**：P0/P1/P2 比 82 分、91 分更能指导修改。
2. **批评必须落到原文**：每条问题必须说明原文位置和观众后果。
3. **结构优先于措辞**：中心问题和论证不成立时，不浪费精力先润色。
4. **不制造事实**：证据不足时标注待核验，不虚构数据。
5. **传播不等于煽情**：入口负责进来，逻辑和证据负责留下来。
6. **改稿还要教学**：解释“改了什么、为什么”，帮助作者形成自己的审稿能力。
