# Acceptance Tests

用于测试 Skill 是否真的在做“批判性审稿”，而不是普通润色。

## Test 1 — 只有主题，没有中心问题

### 输入
“今天跟大家聊聊家庭教育。家庭教育很重要，家长要多关注孩子……”

### 必须做到
- 将“家庭教育”识别为主题，不当成中心问题；
- 至少给出一个 P0：缺少中心问题/目标受众具体困境；
- 不直接进入措辞润色；
- 重构时先提出一个可回答的问题，但要明确这是建议的重构方向，不是假装原稿已经提出。

## Test 2 — 强钩子，弱证据

### 输入
“90%的人都不知道，AI正在让你变笨……”

### 必须做到
- 不能因为开头有冲击力就判断为好稿；
- 标记“90%”需来源；
- 检查“AI让你变笨”的因果强度；
- 改稿不得保留无依据数字作为事实；
- 可以改成条件化、更可证实的判断。

## Test 3 — 实用内容但没有强情绪

### 输入
“Windows 出现 DLL 报错时，先运行 SFC，再根据日志判断是否需要 DISM……”

### 必须做到
- 不强迫加入愤怒、焦虑、争议；
- 优先把专业流程翻译成用户后果和使用场景；
- 允许“强实用价值”本身成为入口。

## Test 4 — 故事很好，但没有知识交付

### 输入
长篇讲述被同事甩锅，结尾只有“所以职场真的很复杂”。

### 必须做到
- 肯定故事承载能力，但指出认知闭环缺失；
- 要求从事件中提炼可迁移判断；
- 不能只继续强化戏剧性。

## Test 5 — SRT 输入

### 输入
包含序号、时间码、ASR 断句错误的字幕。

### 必须做到
- 忽略时间码进行语义分析；
- 不把字幕断句当作者逻辑错误；
- 可用时间范围定位核心问题；
- 最终改稿默认输出连续口播。

## Test 6 — 证据缺口

### 输入
原稿说“某平台用户平均只停留 1.2 秒”，但无来源。

### 必须做到
- 标记需核验；
- 默认改稿不能自行补机构名或研究；
- 若保留，需弱化或使用证据占位。

## Test 7 — 不要模板化开头

连续输入三篇不同稿件。

### 必须做到
- 不要三篇全部改成“你有没有发现……”；
- 根据题材选择问题、场景、结果、冲突、事实或故事入口。

## Test 8 — “案例 ≠ 普遍规律”

### 输入
“我把标题改了以后播放从 500 到 3 万，所以标题决定播放量。”

### 必须做到
- 指出案例只能支持“标题/入口可能产生显著影响”；
- 不能把单案例当因果定律；
- 建议更准确结论。

## Test 9 — 保守修改模式

用户明确：“不要大改，只修逻辑硬伤。”

### 必须做到
- 保留段落顺序、案例和作者语气；
- 只优先修 P0/P1；
- 不擅自更换中心观点。

## Test 10 — 强重构模式

用户明确：“逻辑不成立就全部重构。”

### 必须做到
- 可以重排；
- 必须先说明原逻辑为什么断；
- 新结构必须能追溯到原稿主题和事实；
- 不制造新事实。

## Test 11 — 概念偷换

### 输入
“选题就是让人进入内容。情绪能让人进入。所以短视频的本质就是情绪。”

### 必须做到
- 指出“入口”被缩窄成“情绪”；
- 区分“情绪是入口之一”和“情绪等于全部入口”；
- 标记为概念偷换；若这是全文核心结论，通常应为 P0。

## Test 12 — 结论升级

### 输入
前文只展示两个改标题后播放上升的案例，结尾说：“标题决定一条视频的生死。”

### 必须做到
- 明确写出“正文最多支持什么”与“结尾升级成什么”；
- 不能只说“太绝对”；
- 必须指出论证强度不匹配。

## Test 13 — 假二选一

### 输入
“观众刷短视频不是来学知识的，而是来听故事的，所以别讲干货。”

### 必须做到
- 标记“故事 vs 干货”为假二选一；
- 给出更准确的分工关系：故事可负责进入/承载，干货负责交付；
- 改稿不能简单删除知识部分。

## Test 14 — 相关不等于因果

### 输入
“我把视频开头从知识点改成故事，播放从 500 涨到 10 万，所以故事让算法给了更多流量。”

### 必须做到
- 区分可观察变化与算法因果解释；
- 不得虚构平台算法机制；
- 降低为“这个改动可能影响了停留/传播表现”等条件化表达。

## Test 15 — 内容复杂度与入口复杂度

### 输入
“复杂内容没流量，所以知识型账号一定要把内容做浅。”

### 必须做到
- 明确区分内容深度和入口理解成本；
- 不接受“做浅”作为默认方案；
- 推荐“低门槛入口 → 逐层深入”的结构。

## Test 16 — 大入口，窄承接

### 输入
减脂账号用“上班太累了，你为什么还要逼自己”做开头，后文全程讲职场焦虑，没有回到减脂。

### 必须做到
- 指出入口虽然扩大，但核心主题承接失败；
- 不能把高共鸣自动判断为好选题；
- 重构需把共同情绪带回减脂的可持续性、饮食或训练问题。

## Test 17 — 命题稳定稿不要硬挑逻辑漏洞

### 输入
一篇中心问题明确、案例只做示例、因果措辞克制、结尾与正文一致的稿件。

### 必须做到
- 八大逻辑扫描可以明确写“未发现核心风险”；
- 不得为了体现批判性而虚构概念偷换或因果问题；
- 可以把重点转向节奏、表达和证据增益。

## 总体验收标准

一次合格输出应让作者在看完后同时得到：

1. **我这篇稿子哪里有问题**；
2. **为什么这是问题**；
3. **观众为什么会因此流失/不信/听不懂**；
4. **这次怎么改**；
5. **下一次我自己如何发现同类问题**。

只完成“给一篇更好的改稿”，视为不合格。


## Test 18 — 类比越界

### 输入
“公司管理员工要用 KPI 和奖金，所以教育孩子也应该照搬 KPI 和奖金制度。企业管理已经证明这套方法有效。”

### 必须做到
- 识别“企业管理 → 儿童教育”的类比；
- 明确指出两者可以在“目标清楚、反馈及时”等局部维度相似，但不能由此推出整套机制适用；
- 区分类比的解释功能和证明功能；
- 指出至少一个可能改变结论的关键差异，例如契约关系、发展阶段、亲密关系或权力结构；
- 改稿可以保留类比，但必须降级为辅助理解，不能继续充当核心证据。

## Test 19 — 目标—手段反噬

### 输入
“我们最终要让孩子摆脱外部奖励、学会自主学习。所以每次只要他主动一点，我们都要不断用奖品和父母夸奖强化，直到他越来越依赖这种认可。”

### 必须做到
- 明确写出最终目标：减少外部依赖 / 增加自主性；
- 明确写出主要手段：持续增加外部奖励和父母认可；
- 指出手段可能强化作者想消除的外部依赖；
- 不能简单得出“所有奖励都不好”；
- 优先建议阶段性使用、奖励权重下降、自我评价增加、退出机制等修正方向。

## Test 20 — 短期有效不等于长期正确

### 输入
“恐惧式提醒能让用户马上行动，所以我们应该持续用恐惧内容帮助他们降低焦虑。”

### 必须做到
- 区分短期转化效果和长期目标；
- 检查手段是否可能长期强化焦虑；
- 标记目标—手段反噬风险；
- 若没有长期证据，不得从“马上行动”推出“长期降低焦虑”。



## Test 21 — 播放量不是账号成功本身

### 输入
“我们做垂直知识账号，最重要的目标就是把播放量做大。只要播放越来越高，就说明账号越来越成功。所以哪怕吸引来的大部分人并不关心我们的专业内容，只要播放高就继续做。”

### 必须做到
- 识别最终目标与代理指标的混淆；
- 指出播放量可以是传播代理指标，但不自动等于“垂直账号成功”；
- 不得自行武断指定唯一最终目标；若原稿只说“成功”，应指出成功标准需要明确；
- 至少提出目标用户占比、关注/复访、后续内容承接、转化或信任等可选护栏指标；
- 不得简单结论为“播放量没用”。

## Test 22 — 分数与真正学习

### 输入
“孩子这次考试从 80 分到 95 分，所以说明我们的学习方法已经让他真正理解了这门课。以后只要分数继续涨，就证明理解越来越深。”

### 必须做到
- 识别“分数”是可能有价值的代理指标，不等于全部学习目标；
- 指出分数提高可以支持“表现改善”，但不足以单独证明“理解越来越深”；
- 建议根据目标补充解释能力、迁移任务、延迟回忆等指标；
- 不得否认考试分数的参考价值。

## Test 23 — 短期转化与长期价值

### 输入
“这套强焦虑标题让点击率和当期转化率都提高了，所以它一定更有利于品牌长期发展。”

### 必须做到
- 识别点击率/当期转化是短期代理指标；
- 标记“短期指标 → 长期品牌价值”的结论升级；
- 同时检查目标—手段反噬：焦虑策略是否可能伤害长期信任；
- 建议增加留存、复购、退款、投诉、长期转化或品牌信任等护栏指标。

## Test 24 — 代理指标本身合理，不要过度批判

### 输入
“这个账号本月目标是提高新用户触达，所以我们暂时把独立新观众数作为主要指标，同时看关注率，防止只是获得一次性流量。”

### 必须做到
- 不得为了体现批判性而硬判“指标错位”；
- 应认可“新观众数”与“提高新用户触达”之间具有直接对应关系；
- 注意到关注率已经作为护栏指标；
- 可以提示仍需结合业务目标，但默认应判为“未发现明显代理指标错位”。
