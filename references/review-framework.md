# 口播批判性审查框架

这份文件给出更细的判断问题。使用时选择与稿件相关的项目，不要机械全部输出。

## 1. 问题价值

问：
- 原稿在回答一个问题，还是只介绍一个主题？
- 这个问题是否真实存在？
- 它是否有明确后果、利益、选择或认知冲突？
- 如果删除这条视频，目标受众会损失什么？

危险信号：
- “今天聊聊……”后没有具体问题；
- 只是知识罗列；
- 只是作者觉得有趣，观众没有明显理由关心。

## 2. 用户相关性

问：
- 谁会在第一句意识到“这是我的事”？
- 是作者经历，还是观众问题？
- 专业知识有没有被翻译成普通人的后果？

常用转换：

```text
我的经历 → 我们共同遇到的问题
我的技能 → 不会它会发生什么
我的知识 → 做错会付出什么代价
我的观点 → 观众正在做的选择
```

## 3. 入口

入口不是标题本身，而是“用户进入内容的理由”。

常见入口力量：
- 明确损失
- 明确收益
- 自我相关
- 反常识
- 预期差
- 未完成事件
- 争议但可论证的问题
- 具体困境
- 强画面场景

好的入口：一听就知道“发生了什么 + 为什么跟我有关 + 我还缺什么答案”。

坏的入口：
- 纯背景；
- 先自我介绍很久；
- 术语；
- 大而空的判断；
- 只有情绪，没有实际内容承诺。

## 4. 大入口，窄承接

传播型知识内容的理想结构：

```text
大众可感知的问题 / 情绪 / 冲突
→ 具体专业问题
→ 专业解释
→ 核心目标用户得到解决方案
```

若入口很大众，正文却继续泛泛谈情绪，没有回到专业价值，属于“入口扩大、内容稀释”。

## 5. 理解成本

高理解成本表现：
- 句首连续出现三个陌生概念；
- 先定义再定义；
- 同一句中有多层从句；
- 需要记住前文多个变量；
- 抽象名词密集。

降低方法：
- 先场景后概念；
- 一句只推进一个关系；
- 用具体后果解释抽象名词；
- 先给现象，再解释机制。

## 6. 认知推进

每 1–3 个逻辑段至少发生一次推进：
- 新事实；
- 新原因；
- 反转；
- 更深机制；
- 反例；
- 边界；
- 更精确结论。

若只是连续举三个例子证明同一句话，可能产生停滞。

推荐结构：

```text
我原来以为 A
→ 但出现 B
→ B 为什么出现？
→ 因为 C
→ C 说明 A 需要修正
→ 更准确的结论 D
```

## 7. 论证

逐个核心结论问：
- 这是事实、解释、判断、预测还是价值主张？
- 它由什么支持？
- 支持材料能支持到什么强度？
- 有没有从个案跳到总体？
- 有没有把“可能”说成“必然”？
- 有没有把相关关系讲成因果关系？
- 有没有省略关键中间环节？

常见断裂：

```text
A 后发生 B
≠ A 导致 B

一个案例成功
≠ 这个方法普遍有效

用户有情绪
≠ 用户一定会转化/关注

入口扩大
≠ 内容质量不重要
```

## 8. 故事

故事的作用：
- 降低理解成本；
- 让抽象问题落地；
- 给因果关系提供可观察载体；
- 制造悬念。

故事必须被“回收”：

```text
事件
→ 发生了什么
→ 为什么发生
→ 它说明什么
→ 回到中心问题
```

不要用故事替代证据。故事可以说明“存在这种情况”，不自动证明“多数情况如此”。

## 9. 冲突与反差

寻找真实的“不能同时轻易成立”：
- 速度 vs 深度
- 省钱 vs 隐性成本
- 专业度 vs 理解门槛
- 眼前收益 vs 长期代价
- 直觉判断 vs 实际结果
- 个体最优 vs 系统最优

反差的核心不是夸张，而是“预测误差”。

## 10. 节奏

删除候选：
- 已被前句包含的同义句；
- 已经证明后继续堆的同类例子；
- 不改变判断的背景信息；
- 对中心问题没有作用的旁支。

保留：
- 必要因果环节；
- 关键事实；
- 能让抽象观点落地的具体例子；
- 边界条件；
- 真正推进理解的转折。

## 11. 口语化

口语化不是：加入大量“其实、就是说、你知道吧”。

真正的口语化：
- 短句；
- 清楚主语；
- 一次说一个关系；
- 自然追问；
- 允许停顿；
- 用听觉能区分的结构；
- 重要结论先简单说，再解释。

## 12. 结尾

结尾至少完成一件事：
- 回答开头的问题；
- 修正观众原来的判断；
- 给一个决策规则；
- 给一个可执行动作；
- 给一个可复述的结论。

推荐“认知闭环”而非机械 CTA：

```text
所以问题不是 X，真正该看的是 Y。
以后遇到 Z，先问自己 A，而不是直接做 B。
```

## 13. 七大逻辑风险扫描器

这是 V3 的强制逻辑层。尤其适用于观点口播、知识口播、经验方法论、商业/教育/AI/自媒体类内容。

### 13.1 概念偷换

检查方法：把关键名词逐段写出来，看它的含义是否一致。

常见形式：

```text
“入口” → “情绪入口” → “情绪” → “短视频本质”
“提高效率” → “节省时间” → “效果更好”
“有帮助” → “必要” → “唯一方案”
```

后一项通常比前一项更强，不能默认等价。

### 13.2 结论升级

建立三栏：

| 层级 | 要写清楚什么 |
|---|---|
| 开头命题 | 作者要证明什么 |
| 正文支持上限 | 现有材料最多支持什么 |
| 结尾命题 | 作者最后声称了什么 |

若结尾明显强于“正文支持上限”，优先标为 P0。

常见升级词：
- 可能 → 一定
- 有影响 → 决定
- 常见 → 都是
- 一个有效方法 → 最有效 / 唯一方法
- 一个重要因素 → 本质

### 13.3 个案外推

证据强度粗略分层：

```text
单个案例：证明“这种情况存在 / 可能发生”
多个案例：证明“并非孤例”，仍未自动证明普遍性
系统样本/可靠统计：更适合谈频率或普遍程度
机制 + 数据 + 对照：才更接近较强因果判断
```

不要把这个层级写成数学定律，只作为审稿时控制论证强度的启发式。

### 13.4 假二选一

遇到“不是 A，而是 B”“观众不要 A，只要 B”时必须检查：
- A 和 B 是否真的互斥？
- 是否更准确地描述为先后关系、分工关系或条件关系？

例如：

```text
故事 vs 干货
→ 故事负责降低进入成本，干货负责交付价值

流量 vs 专业
→ 入口可以更大众，承接仍可保持专业
```

### 13.5 相关 → 因果

检查是否出现：

```text
做了 A
随后 B 变好
所以 A 导致 B
```

若缺少对照或其他解释，建议降级为：
- “A 可能是其中一个因素”
- “至少说明改变 A 后结果可能发生明显变化”
- “这个案例提示我们值得进一步检查 A”

### 13.6 类比越界

类比的安全用法：

```text
A 与 B 在 X 点相似
→ 用 A 帮助理解 B 的 X
```

危险用法：

```text
A 与 B 有一点相似
→ A 的整套规律适用于 B
→ 所以 B 应该按 A 的方法处理
```

审查四问：
1. 作者明确说出“相似的是哪一点”了吗？
2. A 与 B 有没有会改变结论的关键差异？
3. 类比只是解释，还是已经承担了证明任务？
4. 删除类比以后，原结论是否还有独立依据？

典型例子：
- 企业管理员工 → 儿童教育
- 健身训练肌肉 → 训练大脑
- 投资组合 → 人际关系
- 机器系统 → 人的心理

这些都可以做启发，但不能因为“像”就默认规律可迁移。

### 13.7 目标—手段反噬

先画一条链：

```text
最终目标
→ 当前手段
→ 短期效果
→ 长期依赖 / 副作用
→ 是否仍接近最终目标？
```

重点检查：
- 手段是否会强化原本要减少的依赖？
- 手段有没有退出机制？
- 短期指标改善是否以长期目标受损为代价？
- 作者是否只证明“短期有效”，却默认“长期也正确”？

典型结构：

```text
目标：培养自主性
手段：持续依赖外部奖励
风险：为了提高自主性，反而强化外部驱动

目标：减少焦虑
手段：不断使用恐惧式提醒
风险：短期促进行动，长期强化焦虑

目标：培养独立判断
手段：每次都直接给标准答案
风险：提高即时正确率，却可能削弱独立判断练习
```

发现这类问题时，不一定要否定手段；优先检查“阶段性使用 + 退出机制 + 权重逐渐下降”能否解决。

## 14. 内容复杂度 ≠ 入口复杂度

审稿时必须区分：

```text
内容深度：这件事本身需要多深的解释
入口成本：观众要花多少认知努力才知道“这跟我有什么关系”
```

目标不是把所有内容变浅，而是：

```text
低门槛入口
→ 具体问题
→ 逐层深入
→ 高价值结论
```

因此，“越复杂越没流量”通常不是一个足够严谨的结论；更准确的审查问题是：“复杂性是否被放在了错误的位置？”

## 15. 大入口，窄承接

若为了传播扩大入口，必须检查正文能否回到目标受众。

```text
大众问题 / 情绪 / 反差
→ 目标人群的具体困境
→ 专业机制
→ 可迁移判断 / 方法
```

危险信号：
- 开头谈所有人都关心的焦虑，正文仍停留在泛情绪；
- 为扩大流量稀释专业主题；
- 标题与核心受众脱节；
- 播放可能增加，但吸引来的不是后续内容需要的人。
